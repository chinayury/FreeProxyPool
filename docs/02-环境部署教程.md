# 02 - 环境部署教程

## 环境要求

| 项 | 要求 |
|----|------|
| Python | 3.12 及以上 |
| Redis | 5.x 及以上（权威存储，必装） |
| MySQL | 8.0（可选，仅冷存储归档用，默认关闭） |
| Docker | 20.10+（可选，容器化部署用） |
| Docker Compose | v2（可选，容器化部署用） |

## 安装方式

### 方式一：源码安装（开发 / 本地调试）

```bash
# 1. 进入项目根目录
cd FreeProxyPool-免费代理IP池系统

# 2. 安装依赖（可编辑安装，源码改动即时生效）
pip install -e .

# 如需运行自检套件（需要 httpx 等测试依赖）：
pip install -e ".[dev]"
```

安装后会生成 `freeproxypool` 命令（console_scripts 入口），等价于 `python -m freeproxypool`。

### 方式二：Docker 部署（生产推荐）

```bash
# 1. 准备配置（必填项未设置时 compose 会直接报错，这是刻意设计）
cp .env.example .env
python -c "import secrets;print('API_KEY =', secrets.token_urlsafe(32))"
python -c "import secrets;print('ADMIN_PASSWORD = Fp#'+secrets.token_urlsafe(14))"
# 把上面两行结果填进 .env 的 API_KEY 与 ADMIN_PASSWORD

# 2. 构建并启动
docker compose up -d --build

# 3. 查看状态
docker compose ps
```

## 配置说明

配置优先级：**环境变量 > Redis 配置 Hash（后台热更新） > `setting.py` 默认值**。

必填项（`.env`）未设置时 compose 直接报错退出——宁可起不来，也不默用弱口令/空密钥对外服务。

### 必填：安全底线

| 变量 | 说明 | 生成方式 |
|------|------|----------|
| `API_KEY` | 对外 API 鉴权密钥。开启后所有分发接口要求请求头 `API-KEY: <值>`。留空 = 不鉴权（仅限受控内网） | `python -c "import secrets;print(secrets.token_urlsafe(32))"` |
| `ADMIN_PASSWORD` | 管理后台口令。要求长度 ≥ 10，且大写/小写/数字/特殊字符至少命中 3 类。写入 Redis 前 PBKDF2 哈希，明文不落库 | `python -c "import secrets;print('Fp#'+secrets.token_urlsafe(14))"` |

### Redis

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `REDIS_PASSWORD` | `fpp_redis_2024` | Redis requirepass 口令 |

### 网关

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `HTTP_PORT` | `5020` | Nginx 映射到宿主机的端口 |
| `TRUSTED_PROXIES` | 空 | 可信反向代理网段（CIDR）。留空 = 完全不采信 X-Forwarded-For（最安全） |
| `ALERT_WEBHOOK` | 空 | 告警 Webhook（钉钉/企微机器人），留空只写日志与后台面板 |

### 延迟分层

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `TIER_FAST_MS` | `500` | fast 档延迟阈值（毫秒） |
| `TIER_MEDIUM_MS` | `2000` | medium 档延迟阈值（毫秒） |

### MySQL 冷存储（可选）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `MYSQL_ENABLED` | `false` | 是否启用 MySQL 归档 |
| `MYSQL_ROOT_PASSWORD` | — | MySQL root 口令 |
| `MYSQL_USER` | `fpp` | 归档库用户 |
| `MYSQL_PASSWORD` | — | 归档库口令 |
| `MYSQL_DATABASE` | `fpp` | 归档库名 |

> MySQL 仅用于事后追溯（proxy_history / access_log / source_config / system_config 四张表），
> 不参与实时代分发与校验。默认关闭，需要归档时用 `MYSQL_ENABLED=true docker compose --profile archive up -d`。

## 启动方式

### 源码启动（分进程）

```bash
# 离线自检（不依赖 Redis / MySQL，验证安装正确性）
python -m freeproxypool selftest

# 查看版本
python -m freeproxypool version

# 启动各服务（生产建议分进程，scheduler 单副本）
python -m freeproxypool collector     # 采集服务
python -m freeproxypool validator     # 验证服务
python -m freeproxypool scheduler     # 调度服务（单副本）
python -m freeproxypool server        # API 网关

# 本地调试：单进程跑全部（仅调试用，生产请分进程）
python -m freeproxypool all
```

启动前需设置环境变量（或写入 `.env`）：

```bash
export DB_CONN="redis://:your_password@127.0.0.1:6379/0"
export API_KEY="你的密钥"
export ADMIN_PASSWORD="强口令（至少10位，含3类字符）"
```

### Docker 启动

```bash
docker compose up -d --build          # 启动全部服务
docker compose up -d --build --scale gateway=3   # 网关扩到 3 副本
docker compose down                    # 停止
docker compose down -v                 # 停止并删除数据卷
```

### 部署脚本

在目标服务器上（已安装 Docker + Compose，已有 `.env`）：

```bash
cd /opt/FreeProxyPool
bash deploy.sh
```

## 部署检查清单

- [ ] `.env` 中 `API_KEY` 与 `ADMIN_PASSWORD` 已设置为强值，未使用默认值
- [ ] `TRUSTED_PROXIES` 按实际网络拓扑配置（前置 Nginx 时填 Nginx 所在网段，否则留空）
- [ ] Redis 健康检查通过（`docker compose ps` 中 redis 状态为 healthy）
- [ ] 网关健康检查通过：`curl http://<公网IP>:5020/health`
- [ ] 版本信息正确：`curl http://<公网IP>:5020/version`
- [ ] 代理统计可访问：`curl -H "API-KEY: <你的Key>" http://<公网IP>:5020/count/`
- [ ] 管理后台可登录：`http://<公网IP>:5020/admin`

## 常见问题

**Q：`docker compose up` 报错 "API_KEY 必须设置"？**
A：`.env` 中 `API_KEY` 或 `ADMIN_PASSWORD` 未设置。这是刻意设计，填入强值后重启。

**Q：源码启动报 `ModuleNotFoundError: No module named 'freeproxypool'`？**
A：未安装包。执行 `pip install -e .`，或设置 `PYTHONPATH` 指向 `src/`：`export PYTHONPATH=$PWD/src`。

**Q：网关启动后鉴权类接口全部 503？**
A：Redis 不可达。配置中心采用 fail-closed 语义，Redis 故障时鉴权类请求返回 503（拒绝服务而非放开大门）。检查 Redis 连接与 `DB_CONN`。

**Q：健康检查一直 unhealthy？**
A：确认容器内能连通 Redis。collector/validator 的健康检查会执行 `cc.get_redis().ping()`，Redis 不通即 unhealthy。

**Q：首次登录管理后台被强制改密？**
A：仍在使用默认口令。`ADMIN_FORCE_PASSWORD_CHANGE` 生效，按提示修改即可。

**Q：如何启用 MySQL 归档？**
A：设置 `MYSQL_ENABLED=true`，用 `docker compose --profile archive up -d` 启动 mysql 服务。
