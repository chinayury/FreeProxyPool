## 三、本轮采纳的借鉴点

### 1. 校验目标看护（unavailable ≠ failed）

- **来源**：maximilianfeix/proxy-scraper 的 check-states 设计 ——
  「A check target that is down doesn't fail the proxies checked against it」
  （探测目标宕机不给代理记失败）与「A check that didn't run is never passed」
  （没跑过的检查永远不算通过）。
- **要点**：把「目标故障」与「代理失效」两种失败严格分离；目标不可达时的
  失败记为 unavailable（本项目落地为 `deferred`），不进入任何惩罚链路。
- **本项目落地**：`helper/check.py` 目标看护 —— 连续 `fail_http` 达
  `TARGET_GUARD_THRESHOLD` 且目标直连探测不可达（带 `TARGET_GUARD_TTL` 缓存）
  时改判 `deferred`；HTTPS 能力探测失败在目标不可达时保留旧值。
  实现细节与根因分析见 [05-开发日志](05-开发日志.md)「校验目标故障毒化整池」。
- **为什么重要**：旧语义下一次 httpbin.org 故障就会毒化整池
  （退避 → streak 清零 → 错误率抬升 → 淘汰），这是同类项目用真实运维教训换来的防线。

## 五、未采纳及理由（取舍原则备忘）

| 扩展 | 来源项目 | 不采纳理由 |
|---|---|---|
| 隧道代理/前向转发模式（固定本地端口轮换上游） | ProxyCat、Resin、scylla、proxy-scraper | 功能定位超出「代理分发 API」边界：README 合规声明明确不鼓励搭建流量中转代理；CONNECT 隧道/粘滞会话/上游认证属重大架构扩展，超出单轮维护半径。如确有需求建议开 issue 单独立项评估。 |
| MCP server（AI 代理获取接口） | proxy-scraper | 依赖最小化约束 + 当前用户群无明确需求；待 MCP 生态需求明确后再评估。 |
| Web UI 地理分布地图 | scylla | 前端地图库属重量级依赖，违反依赖最小化约束。 |
| Kubernetes 部署清单 | Python3WebSpider | 当前部署形态为 docker compose（测试服务器），K8s 清单无消费者、维护成本高。 |
| Telegram 频道爬取源 | wzdnzd/aggregator | 需 TG API 凭据、合规风险高，暂不引入。 |
| works-with 目标可达性清单（google.txt 等） | proxy-scraper | 每目标一次探测请求成本高；已有延迟分层与匿名度维度，边际收益有限。 |
