## 缺陷修复（现象 → 根因 → 解决方案）

### 管理后台总览面板恒空白（中危，2026-11-14）

- **现象**：任何浏览器打开管理后台「总览」页，统计卡片与五个分布面板（采集源/地域/延迟分层/传输协议/任务进度）全部空白，且无控制台报错——异常被 `.catch` 的 toast 静默吞掉（2.6 秒后消失）；「代理资源池」视图正常。
- **根因**：`loadOverview()` 的渲染回调里，延迟分层段落 `var t = document.getElementById('tierStats')` 发生了 `var` 声明提升，遮蔽了全局 i18n 函数 `t()`。回调内第一次调用 `t('stat.pool')` 时 `t` 已是未赋值的提升变量，抛 `TypeError: t is not a function`，整个回调中断——所有面板都渲染不出来。这是典型的 JS `var` 提升陷阱：声明写在后面，遮蔽却覆盖整个函数作用域。
- **解决方案**：该变量改名 `tEl`（并同步 `tEl.innerHTML` 赋值行），同时在原处加注释说明该变量不得命名为 `t`，防止回归。全文扫描确认 `admin.html` 内无其他 `var t =` 遮蔽点。部署后用无头 Chrome + CDP 真实登录后台截图验证：总览页统计卡片与五个分布面板全部正常渲染（修复前同一方法实测为空白）。

### 校验目标故障毒化整池（中危，2026-11-14）

- **现象**：HTTP 校验目标（默认 `httpbin.org`）自身宕机或被墙时，每轮存量复检里全部代理都会以 `fail_http` 判负：进退避黑名单（1h→2h→6h→24h）、`streak` 清零、错误率抬升，多轮之后触发错误率淘汰——一次目标故障就能把健康的池子拖成空池。HTTPS 目标宕机时同理，全池代理的 HTTPS 能力会被抹成 `False`，`type=https` 筛选从此全部落空。
- **根因**：`fail_http`（软失败）把"探测目标不可达"与"代理失效"混为一谈。旧代码注释里已意识到"校验目标自身故障时可能整池都不通过"，但只做了一半保护（不清池成员资格），惩罚链路（退避 / streak / 错误率）照罚不误；HTTPS 能力更是无条件覆盖。
- **解决方案**：引入**校验目标看护**（借鉴 maximilianfeix/proxy-scraper 的 check-states 语义："探测目标宕机 ≠ 代理失效"、"没跑过的检查永远不算通过"）。连续 `fail_http` 达阈值（`TARGET_GUARD_THRESHOLD`，默认 20）且目标直连探测不可达（带 `TARGET_GUARD_TTL` 缓存）时判定目标疑似故障，本批失败改判 `deferred`——不退避、不清 streak、不计错误率、不淘汰，池内状态原地保留，目标恢复后自动重验；直连可达则立即恢复惩罚语义（避免把"一批烂代理"误判成目标故障）。HTTPS 探测目标不可达时能力值置 `None` 保留旧值（沿用属性稳定哲学，与 anonymous/region/ip_type 的 keep_known 对齐）。新增统计键 `deferred`，不变式升级为 `passed + failed + deferred == checked`，通过率分母剔除 deferred。自检新增 `test_target_guard` 覆盖目标健康/疑似故障/恢复/HTTPS 保值四类场景。

### 鉴权 Redis 故障绕过（高危）

- **现象**：Redis 不可用时，`API_KEY` 配置读取失败后静默回落为空串，导致鉴权直接关闭，所有分发接口裸奔。
- **根因**：配置中心 `get()` 捕获任何异常后静默返回默认值，安全参数与普通参数用同一套读取逻辑，属典型 fail-open。
- **解决方案**：拆分双语义读取——`get()`（普通参数，Redis 异常回落默认，保可用）与 `get_secure()`（安全参数，读不到即抛 `BackendUnavailable` 503，fail-closed）。安全参数一律走 `get_secure`。自检覆盖该回归：模拟 Redis 故障，断言鉴权不放开、限流不放开。

### 登录爆破绕过（高危）

- **现象**：攻击者伪造 `X-Forwarded-For` 头，每次登录失败换一个"IP"，绕过登录失败锁定。
- **根因**：登录失败计数直接拼接不可信的 XFF 头，未校验来源可信性。
- **解决方案**：默认完全不采信 XFF，一律使用 TCP 对端地址；仅当直连来源命中 `TRUSTED_PROXIES` 网段时才采信 XFF 首项。锁定 Key 做哈希归一化，超长伪造值不会撑大 Key。

### ADMIN_ENABLED 开关失效（高危）

- **现象**：关闭管理后台（`ADMIN_ENABLED=0`）后，`/admin/api/*` 接口仍可访问，开关形同虚设。
- **根因**：旧版 `ADMIN_ENABLED` 只作用于 HTML 页面，后台 JSON API 不检查该开关。
- **解决方案**：开关改为路由级依赖，作用于**整个** `/admin` 前缀。关闭后登录接口与所有后台接口统一返回 401。

### 采集源 URL SSRF（高危）

- **现象**：后台可覆盖采集源 URL，传入 `file:///etc/passwd`、`gopher://` 等协议读取内网资源。
- **根因**：采集源 URL 覆盖未做协议白名单与内网地址校验。
- **解决方案**：`validate_fetch_urls` 做协议白名单（仅 `http`/`https`）+ 内网/保留地址黑名单 + 数量上限。Webhook、校验目标 URL 同样校验，杜绝服务端主动请求的 SSRF 入口。

### area 过滤失效（中危）

- **现象**：`?area=CN` 过滤不生效，返回全池代理。
- **根因**：地域筛选未严格匹配，非法/缺失地域静默回落成"不过滤"。
- **解决方案**：地域索引 `{table}:region:{CODE}` 实现 O(1) 取数；非法 `area` 显式 400，不再静默忽略；索引不可用时退回全表扫描但**只改取数方式、不改返回结果**，地域筛选始终严格匹配。

### 熔断不触发（中危）

- **现象**：采集源连续失败，但熔断状态查询把失败计数清空，导致熔断永远攒不到阈值。
- **根因**：`is_tripped()` 在冷却结束判断时 pop 掉整条状态，而每轮采集都查询一次，计数被反复清零。
- **解决方案**：查询本身不清空失败计数；"解析出 0 条即判失败"纳入熔断语义；采集过程中抛异常由 `helper.fetch._collect_one` 兜底记一次失败，确保异常源也能熔断。

### 队列无背压（中危）

- **现象**：验证服务长时间停摆时，待验队列无限增长，最终 OOM。
- **根因**：队列无长度上限，入队不裁剪。
- **解决方案**：`QUEUE_MAX_LEN` 上限 + `LTRIM` 背压裁剪，超出上限丢弃最旧待验代理。

### 校验统计恒空（中危）

- **现象**：自检中 `passed + failed != checked`，校验统计不变式不成立。
- **根因**：格式错误的代理地址在校验前被跳过，未计入 `checked`。
- **解决方案**：`checked` 覆盖全部条目（含格式错误），`passed + failed == checked` 不变式由自检断言守护。

### Prometheus 指标恒 0（中危）

- **现象**：Grafana 上指标曲线恒为 0，告警规则因 0 永远误报。
- **根因**：指标定义了 Gauge 但无任何一处 `.set()`，写入的 Redis stat key 在真实运行进程里不存在。
- **解决方案**：指标由谁写、在哪写全部在采集端显式落 Redis；`update_metrics()` 只做"读取 + set"；无数据源的指标直接删除，避免假曲线。

### 代理地址正则放过畸形输入（中危）

- **现象**：`999.999.999.999:99999`、`01.2.3.4:80`、`1.2.3.4.5:80` 等畸形地址被旧正则放过。
- **根因**：正则只做格式匹配，未校验数值范围与前导零。
- **解决方案**：`core/iputil.py` 统一实现 IP 解析与合法性校验，拒绝端口越界、前导零、五段地址等，全项目唯一实现。

### 日志重复写入与句柄泄漏（工程质量）

- **现象**：管理后台日志面板每条日志出现两遍；长跑进程不断堆积 handler 与文件描述符。
- **根因**：每次实例化 logger 都新建 Redis handler 并打开文件句柄，同一条日志既走自身 handler 又冒泡到 root handler。
- **解决方案**：Redis 汇聚 handler 只允许由 `attach_redis_sink` 挂载一次（挂到 root）；logger 按名字缓存复用，同名多次获取返回同一实例。

### 验证阶段新发现：get_redis() 二次调用崩溃

- **现象**：离线自检全绿，上线后部分接口 500。
- **根因**：`get_redis()` 二次调用时连接池状态异常崩溃，离线自检用内存 Redis 未覆盖该路径。
- **解决方案**：修复连接池复用逻辑，并将该场景补入离线自检，确保"自检绿"与"上线可用"一致。

## 功能新增

- **失效回报接口** `POST /report/`：客户端发现代理失效立即回报，服务端剔除并拉黑，无需等下一轮复检。
- **批量分发接口** `GET /batch/`：一次取 N 个互不重复代理。
- **代理地域完整链路**：GeoIP 解析、双接口容错、Redis 缓存 7 天、并发限流、地域索引 + 优雅降级。
- **代理存活 TTL 与自动回收**：过期索引 + 调度器周期回收。
- **延迟分层 tier**：`fast`/`medium`/`slow`/`unknown` 一等可筛选维度，阈值可配、热生效。
- **死代理指数退避**：黑名单 `1h→2h→6h→24h` 阶梯退避，反复失败代理不再被反复重试。
- **单代理深度诊断 CLI**：`python -m freeproxypool check <ip:port>` 输出分层延迟、出口 IP、匿名度、地域与判定。
- **SOCKS4 / SOCKS5 支持**：传输协议字段、校验分流、域名解析策略、网关筛选、新增 SOCKS 采集源。
- **客户端 SDK + Scrapy 中间件**：同步 + 异步客户端，自动带 Key、自动失效回报、指数退避；SDK 不依赖项目内任何模块。
- **每日质量快照工具**：产出快照 JSON / 纯文本清单 / 按国家分文件 / 静态看板。
- **离线自检套件（710 项）**：内存版 Redis 上运行，覆盖版本、校验、脱敏、安全、存储、分发、鉴权、采集、tier、SOCKS、地域索引等。

## 架构改进

### 删除 Flask，统一 FastAPI

删除整套 Flask 实现（约 770 行），仅保留 FastAPI 一套 API。消除"容器跑 A、命令行跑 B"的双行为风险，安全修复只需改一遍。

### 新增 core 公共层

新增 `core/` 公共层（版本、异常、日志、校验、IP、安全、脱敏），硬性约束不 import 任何业务模块，消除循环导入，全项目唯一实现 IP 判定、脱敏、安全工具。

### 服务边界清晰化

`services/` 三个进程职责严格分离：collector（只扫源入队）、validator（只消费验收入池）、scheduler（只复检/清理/统计/响应手动触发），`CHECK_INTERVAL` 真正生效。

### 存储层 O(1) 化

HTTPS 计数由 `HVALS` 全量扫描改为 `ZCARD` 索引；分发候选由全池反序列化改为 `ZREVRANGE` 窗口，大池下请求不再全量排序。

### 配置中心双语义读取

`get()` 与 `get_secure()` 分离，安全参数 fail-closed，普通参数保可用，从机制上杜绝鉴权类配置的 fail-open。
